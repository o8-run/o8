- The local app server answers only requests addressed to localhost. Requests that name another host, and cross-site writes, are refused before they reach o8.
- Usage analytics are on by default for new installs. The first-run privacy screen lists every event and turns them off in one click, and an earlier opt-out stays off. Events never include code, prompts or file names.
- Usage analytics count the first successful worker launch, first completed merge, and clean or unclean backend session endings. The existing opt-out and first-run gate apply to every event; no content or new identity fields are sent.
- Sent chat images reach the agent. If an image can't be delivered, your draft stays in the composer with the reason.
- When a runtime session is replaced, the chat keeps its context or tells you it was lost, instead of carrying on without it.
- The effort you pick is the effort the worker runs with, including lead and remote workers.
- Switching tabs reuses work already done for hidden transcripts, so busy threads open faster.
- Updates appear right after a release instead of waiting for the next check.
- Dispatch stops within seconds when a worktree can't be prepared, instead of hanging.
- Voice says it's available only when a session can actually start.
- Connectivity checks no longer open their own workspace tabs.
- Terminal approvals apply to the runtime shown in that terminal.
- Agents get clearer CLI help, paged results for large MCP text, and each task's work mode in its scope. Workers launched from source get a verified o8 command.
- Security updates for native dependencies.
- Experimental: o8 next opens from Settings > Experimental and ships inside the app, with a project header and repo chips, task cards with activity steps, and a keyboard shortcuts reference.
