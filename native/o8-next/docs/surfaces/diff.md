# Diff viewer

The opt-in viewer registers in `src/surfaces/diff.rs`. Its source, actions, refusal states and regression test function names are retained from the preceding port head.

The disposable host discovers its fixture entry without shared dispatcher edits. Existing authenticated production routes remain authoritative.

The shared `main.rs`, `client.rs`, `diff.rs`, workspace state, shell view and development host match main. The shell inventory has one entry for this surface. Its Merge and Confirm request adapters use the shared authenticated transport. The shared palette test follows registered tab availability, so the enabled Diff surface opens while unavailable commands still refuse.

Base belongs to the selected packet: opening another packet resets it to that lane's base, while reopening the same packet retains its explicit override. Inline privacy and long-line bounding run in the inline background loader. Standalone parsing and review retain main's behavior.

A held merge retains its approval ID, packet, target, displayed HEAD/source and the server's Git/governance receipt. Confirm re-reads packet/lane identity, stop/runtime state, the diff, the pending continuation and all merge-preview checks. It resolves that exact approval through the desktop approvals route with the frozen receipt, so the server also fences changes before the claim and publication. The retained card's unchanged mission/policy/size requirement can be acknowledged; new failed checks refuse and retain the card. A lost or slow response polls the durable receipt by ID without a second mutation. If the receipt is unavailable or governance changes, Review approval performs a read-only recovery before a separate Confirm.

Existing regression test names are retained; nine round-2 tests extend `shell::test_support`. They cover packet switching, standalone long-line review, completed mission-held and policy-held managed-worktree approvals, seven changed-gate refusals, a late review-change race, repair/retry with the same approval, lost completion, initial receipt failure and explicit review after governance changes. A route test verifies denied operator authentication. The test-only oracle contains stable IDs, revisions, status and fixed route names.
